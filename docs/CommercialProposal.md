## 0. サマリー(結論)

- **現状**: 個人開発・約 1 か月・117 コミットで、ターン制ウォーシミュレーションとして**一通り遊べる状態**に到達しています。ユニット 22 種・地形 15 種・マップ 15 枚・CPU 指揮官 5 人を実装済みで、ゲームロジックは 1,076 件の自動テストで守られています。
- **評価**: 「**商品の中身(ゲーム性)はほぼ出来ている。外側(見た目・音・入口の体験・事業の器)が未整備**」というのが現状の要約です。作り直しは不要で、残る仕事は**仕上げ・入口の体験・法務**です。
- **前提**: アート・サウンドの**外注は行わず、すべて内製**で仕上げます。**開発体制も現行の個人体制を継続**します。したがって追加の外注費はほぼ発生せず、必要なのは**お金より時間**です。
- **提案**: 追加 **9〜15 か月**(個人体制での稼働を前提とした暦の期間)で、**PC 向け買い切り(Steam)+ ブラウザ体験版**の形で商品化することを提案します。ブラウザ版は「無料で遊べる入口」として残し、集客とレビュー獲得に使います。
- **最大の課題は技術ではなく権利と見た目**です。**IP(著作権)の帰属**(業務として進めるのか、個人の資産を会社が扱うのか)は着手前の確定が必要で、**外注しない前提では「内製で有料商品に見える水準へ到達できるか」が企画全体の成否を握ります**(3.2 P-1)。
- **ご判断いただきたいこと**: ①IP の権利帰属と契約形態 ②Phase 1(検証・追加費用ほぼ無し)の実施可否 ③実費(数万円〜十数万円)の負担元 ④法務支援の窓口

### 1.3 技術構成

| 項目 | 内容 | 商用化での評価 |
|---|---|---|
| 言語・エンジン | TypeScript + Phaser 3 + Vite | Phaser 3 は **MIT ライセンス**で商用利用可 |
| 依存ライブラリ | 実行時依存は **Phaser のみ** | ライセンス調査の対象が少なく、権利面のリスクが小さい |
| ロジック分離 | `src/core/` は描画非依存の純粋 TypeScript | テスト容易・他プラットフォームへの移植余地がある |
| データ外部化 | ユニット・地形・マップ・経済パラメータをデータとして分離 | バランス調整でコードを触らずに済む |
| CI/CD | GitHub Actions でテスト → ビルド → GitHub Pages 公開 | 商用配信でもそのまま流用できる |
| セーブ | ブラウザの localStorage(中断 1 件・クリア記録・設定) | 商用では要強化(3.3 参照) |

### 1.4 権利・素材の現状(商用化における強み)

商用化で最も揉めやすいのが素材の権利ですが、本作は**最初から商用化に耐える作り方をしています**。

- **画像素材は 0 件**。ユニットのシルエット・地形・エフェクトはすべて Phaser の描画 API でコードから描いています(`src/rendering/unitIcon.ts` ほか)。
- **音源ファイルも 0 件**。効果音・BGM は Web Audio API による合成音で、楽譜データもオリジナルです(`src/audio/`)。
- 名称・マップ・ユニットデータ・シナリオはすべてオリジナルとして制作しています。
- 既存作品からはゲームシステム(ジャンルの遊び方)のみを参考にしています。

**結論**: 「既存素材の混入」という商用化の典型的な地雷は踏んでいません。ただし、素材が無いこと自体は 3.2 の課題(見た目の商品性)につながります。

### 1.6 ユーザーからの評価(本検討の起点)

周囲の方に遊んでいただいたところ好評だった、というのが今回の起点です。ただし現時点で得られているのは**知人による定性的な感想のみ**で、以下が不明です。

- 何人が / どのマップを / 何分遊んだのか(定量データなし)
- どこで離脱したか、どの要素が評価されたのか
- 「知人だから褒めた」分をどれだけ割り引くべきか

**したがって、本企画の Phase 1 の最重要タスクは「定量的な検証」です**(2.7 参照)。ここを飛ばして開発投資を決めるのは危険であり、本書もその前提で段階的な意思決定ゲートを設けています。

## 2. 商用化の企画

### 2.1 商品コンセプト

> **「1 ステージ 20 分で終わる、考える楽しさだけを詰めた現代版ウォーシミュレーション」**

非商用版のコンセプト(考える楽しさ・レトロで見やすい・地形と相性で戦略が生まれる)は変えません。商用版で足すのは以下の 3 点です。

1. **見た目と音の商品性** — 現在のコード描画・合成音を、プロ品質のドット絵・チップチューンに置き換える
2. **遊び続ける理由** — キャンペーン(マップを順番に攻略する導線)と実績・戦績の可視化
3. **入口の摩擦をゼロにする** — ブラウザで無料の体験版を遊び、気に入ったら製品版を買う導線

### 2.2 ターゲット

| 層 | 内容 | 規模感の考え方 |
|---|---|---|
| メイン | 往年のターン制ウォーシミュレーション経験者(30〜50 代)。「あの遊びをもう一度、短時間で」 | Steam のターン制ストラテジー / ウォーゲーム層 |
| サブ | ストラテジー初心者。ルールが少なく 1 ステージが短いので入門に向く | ブラウザ体験版からの流入 |
| 隠れた強み | **同一画面での対人戦**が実装済み。「1 台で 2 人が交代して遊ぶ」需要(実況・配信・家族/友人プレイ) | 差別化要素として訴求可能 |

### 2.3 プラットフォームと販売形態

| 案 | 内容 | 長所 | 短所 | 評価 |
|---|---|---|---|---|
| **A. Steam(買い切り)** | デスクトップアプリとして販売 | 有料販売の市場が最も大きい。ウィッシュリスト/セールなど販促の仕組みが整っている | 手数料 30%。ストアページ・実績・審査など**ゲーム外の作業が増える**。Web からのラッパー化が必要 | **◎ 本命** |
| B. itch.io(買い切り / 投げ銭) | インディー向けストア。ブラウザ版のまま販売可 | 手数料が低く自由度が高い。ブラウザゲームをそのまま置ける | 集客力が Steam より大幅に小さい | ○ 併売 |
| C. スマホストア(iOS / Android) | ネイティブアプリ化して配信 | 市場は大きい | 縦持ち UI の作り直しが必須。審査・年会費・競争が激しい。**ジャンルとの相性は Steam に劣る** | △ 将来 |
| D. ブラウザ無料 + 広告 | 現状の形のまま広告収益化 | 追加開発がほぼ不要 | 1 ステージ 20 分の腰を据えるゲームは広告インプレッションを稼げない。収益性が低い | × |
| E. 受託 / ライセンス提供 | 他社へのライセンス | 開発費を回収しやすい | 相手先の開拓が必要。本作の強みが活きない | × |

**推奨: A(Steam 買い切り)を本命、B(itch.io)を併売、ブラウザ版は無料体験版として維持。**

ブラウザ版を残すことは、単なる遺産ではなく**販促資産**です。「URL を開くだけで今すぐ遊べる体験版」は、SNS・記事・配信からの導線としてインディーゲームでは強力に機能します。

### 2.4 収益モデル

| 案 | 内容 | 評価 |
|---|---|---|
| **買い切り(推奨)** | 製品版を一度購入すれば全機能。ブラウザ版が無料体験版 | ゲーム性と最も相性が良い。運営コストが小さく、個人〜小規模体制で持続可能 |
| 基本無料 + アイテム課金 | 指揮官・マップの個別販売など | 常時運営が必要。ターン制シングルプレイとの相性が悪い。**非推奨** |
| 買い切り + 有料 DLC | 本編後にマップ・指揮官パックを追加販売 | 現状のデータ駆動設計と相性が良い。**製品版リリース後の第 2 段として推奨** |
| サブスクリプション | — | 本作の規模では成立しない。非推奨 |

### 2.5 価格と売上の試算

**前提(すべて仮置き。検証が必要です)**

- 価格: **1,200 円**(インディーのターン制ストラテジーの標準的な価格帯を想定。要市場調査)
- プラットフォーム手数料: 30%
- 返金・為替・セール値引きの影響として、実収を定価の **55%** と仮定(1 本あたり約 660 円)
- 販売期間: 発売後 12 か月

| シナリオ | 販売本数 | 粗利(概算) | 前提 |
|---|---|---|---|
| 悲観 | 500 本 | 約 33 万円 | 販促がほぼ効かず、ウィッシュリストが伸びない場合 |
| 標準 | 3,000 本 | 約 198 万円 | 発売時ウィッシュリスト 5,000 前後を確保できた場合 |
| 楽観 | 10,000 本 | 約 660 万円 | 配信者・メディアに取り上げられ、セールで伸びた場合 |

**重要**: この試算の不確実性は大きく、本数を約束できるものではありません。一方で**外注を行わないため金銭的な先行投資はごく小さく(実費で数万円〜十数万円)、悲観シナリオでも金銭的な損失はほぼ発生しません**。実質的なコストは開発者の時間(2.8)です。

したがって判断軸は「売上で費用を回収できるか」ではなく、**「7〜12 人月の時間を投じるに値する手応えがあるか」**になります。その手応えを測るのが 2.7 の Phase 1 です。

### 2.7 ロードマップ(意思決定ゲート付き)

一気に投資せず、**各フェーズの終わりで続行判断をする**構成にしています。

| Phase | 期間 | 内容 | ゲート(通過条件) |
|---|---|---|---|
| **Phase 1: 検証** | 1〜2 か月 | 現状のブラウザ版で定量検証。20〜50 人規模のテストプレイ、プレイ時間・離脱・満足度の計測。競合価格調査。権利帰属の整理 | 「30 分以上遊んだ人の割合」「もう一度遊びたい割合」が基準を満たすか。IP 帰属が確定しているか |
| **Phase 2: 商品化設計とアート試作** | 1〜2 か月 | **内製アートの方向性を決め、1 画面ぶんの試作を作る**。キャンペーン構成の設計。価格・配信計画の確定 | **試作が「有料商品に見える」と外部の目で判断できるか**(ここが本企画の最大の関門) |
| **Phase 3: 製作** | 5〜8 か月 | アート/サウンドの内製差し替え、チュートリアル、キャンペーン、テストマップ削除、セーブ強化、Steam 対応 | 縦の 1 ステージが通しで商品水準に到達しているか |
| **Phase 4: 仕上げと審査** | 2〜3 か月 | バランス調整、QA、ストアページ、レーティング取得、法務書類 | 外部テスターの評価・不具合件数が基準以下か |
| **Phase 5: 発売と運用** | 継続 | 発売、不具合対応、DLC / 追加マップ | ウィッシュリスト・売上の実績 |

合計 **9〜15 か月**。個人体制を継続する前提のため、非商用版と同じペース(専業ではない稼働)で暦の期間を見積もっています。Phase 1 は追加費用がほぼ発生しないため、**まず Phase 1 のみ承認いただき、結果を見て Phase 2 以降を判断する**進め方を推奨します。

### 2.8 体制と費用(概算)

**体制: 開発者 1 名(現行の個人体制を継続)。アート・サウンドを含む全工程を内製で行い、外注は行いません。**社内には法務レビューの支援のみお願いしたい、という構成です。

**費用(実費)**

| 費目 | 概算 | 備考 |
|---|---|---|
| Steam 登録料 | 1 作品あたり 100 USD | Steam Direct の手数料。一定の売上に達すると返金される仕組み |
| レーティング取得 | 要確認 | Steam は IARC の自己申告で無料の見込み。他プラットフォームへ広げる場合は別途 |
| QA / プレイテスト謝礼 | 0〜10 万円 | 無償の協力で賄えるなら 0 |
| 制作ツール・フォントライセンス等 | 数千円〜数万円 | 商用利用可のフォント・作図ツールなど |
| 法務(規約・ポリシー整備) | 要確認 | 社内法務で対応いただければ追加費用なし |
| **合計(実費)** | **数万円〜十数万円** | 外注を行わないため、金銭的な先行投資はごく小さい |

**費用ではない、しかし最大のコスト: 開発者の時間**

| 作業 | 工数目安 |
|---|---|
| アートの内製(ユニット 22 種・地形 15 種・UI・タイトル) | 2〜4 人月 |
| サウンドの内製(BGM 増曲・効果音リファイン) | 1〜2 人月 |

| **合計** | **約 7〜12 人月相当**(個人稼働のため暦では 9〜15 か月) |

つまり本企画でお願いしたいのは**予算の承認ではなく、権利関係の整理・法務支援・時間の確保**です。

## 3. 課題

商用化にあたって解くべき課題を、影響の大きい順に整理します。

### 3.1 権利・法務(最優先)

| # | 課題 | 内容 | 対応方針 |
|---|---|---|---|
| L-1 | **IP の権利帰属** | 現在は個人の時間で開発してきた成果物。会社として販売するのか、個人が販売するのか、権利をどう扱うのかが未定。**着手前に確定が必要** | 上長・法務と協議。職務発明規程・副業規程の確認 |
| L-2 | **既存作品との類似** | ゲームシステムはアイデアであり著作権の保護対象外だが、名称・ビジュアル・固有表現が似ると問題になる。現状はすべてオリジナルで作っており実質的なリスクは低い | 現行方針(名称・素材・データはすべてオリジナル)を商用版でも厳守 |
| L-3 | **タイトルの商標** | 「グリッドウォーズ」は仮題。商用化するなら商標調査が必須で、既存商標と衝突する可能性がある | Phase 2 で商標調査 → 必要なら改題。改題は早いほど傷が浅い |
| L-4 | **レーティング** | 戦争を扱うため、プラットフォームによっては年齢区分の取得が必要。Steam は自己申告 + IARC、家庭用は CERO 等 | Phase 4 で対応。配信先によって要件が違うため事前確認 |
| L-5 | **OSS ライセンス** | 依存は Phaser(MIT)のみで商用利用に支障はないが、表記義務がある | クレジット画面にライセンス表記を追加。リポジトリにも LICENSE を整備 |
| L-6 | **利用規約・プライバシーポリシー** | 有料販売・データ計測を行うなら必須。特定商取引法に基づく表記も販売形態により必要 | Phase 4 で整備。販売主体(法人 / 個人)の決定が前提 |
| L-7 | 外部素材を使う場合の権利処理 | **現時点で外注の予定はない**が、3.2 P-1 の方針転換で外部の素材やアセットを使う場合は、商用利用の可否・改変の可否・クレジット表記を確認する必要がある | 方針転換する場合のみ、利用規約の確認と記録を必須手順にする |

### 3.2 プロダクト品質

| # | 課題 | 内容 | 対応方針 |
|---|---|---|---|
| P-1 | **見た目が「商品」に見えない** | グラフィックがコード描画のシルエットのみ。ゲーム内容が良くても、ストアのスクリーンショットで選ばれない。**有料化における最大の障壁であり、外注しない方針のため内製で到達できる水準がそのまま商品性の上限になる** | コード描画を「作風」として設計し直す(統一カラーパレット・シルエットの視認性・動きとエフェクトで情報量を出す)。**Phase 2 で 1 画面ぶんの試作を作り、外部の目で「有料商品に見えるか」を判定する**。届かない場合は、商用利用可のアセット購入・部分外注・無料公開の継続のいずれかへ方針転換する |
| P-2 | サウンドの厚み | 合成音のためレトロさは出ているが、長時間プレイに耐える曲数・音質ではない | 内製で BGM を増曲(既存の楽譜データ形式をそのまま使えるため、追加コストは時間のみ)。効果音もリファイン |
| P-3 | **入口の体験** | チュートリアルがなく、静的なガイドを読む前提。無料なら許容されるが、有料では初回離脱に直結する | 操作しながら覚える導入ステージを実装 |
| P-4 | 遊び続ける理由の薄さ | マップ単品を選ぶ構成で、進行の手応え(章立て・実績)が弱い | キャンペーン導線と実績を追加 |
| P-5 | 難易度設計 | 指揮官選択で難度を変えられるが、「難易度」として明示されていない。激ムズマップは全マップクリアが前提で、購入者の大半が到達しない可能性 | 難易度選択の明示化。解放条件の緩和を検討 |
| P-6 | 縦持ちスマホの UI | 横長レイアウト固定のため、縦持ちだと表示が小さい | PC を主軸にするなら優先度は低い。スマホ展開時に必須 |
| P-7 | 日本語のみ | 海外市場を取りこぼす。Steam では英語対応の有無で本数が大きく変わる | 英語対応は費用対効果が高い可能性があるが、テキスト量(ガイド・図鑑・エンディング)の見積もりが必要 |

### 3.3 技術

| # | 課題 | 内容 | 対応方針 |
|---|---|---|---|
| T-1 | **セーブデータの堅牢性** | localStorage に中断 1 件のみ。ブラウザのデータ削除・シークレットモード・容量超過で消える。無料なら許容範囲だが、有料商品では**クレームに直結する** | 複数スロット化、破損時の復旧、バージョン間の移行処理。Steam 版はクラウドセーブ対応 |
| T-2 | Steam 配信のためのアプリ化 | 現状はブラウザ前提。デスクトップアプリ化(Tauri / Electron)と、実績・クラウドセーブの連携が必要 | Phase 3 で対応。ロジックが描画非依存のため移植負荷は比較的小さい |
| T-3 | 動作環境の保証範囲 | 対応ブラウザ・OS・解像度の動作保証を定義しておらず、サポート範囲が不明確 | 動作環境を明記し、代表構成で検証 |
| T-4 | ブラウザ版のソース保護 | Web 配信ではクライアントコードが閲覧可能。体験版として割り切る前提なら問題ないが、製品版と同じビルドを置くと有料版の内容が露出する | 体験版はマップ・機能を制限した別ビルドにする |
| T-5 | UI の自動テストが無い | ロジックは 1,076 ケースで守られているが、画面・演出まわりは手動確認のみ。商用版では回帰不具合が致命傷になる | 主要導線のスモークテスト自動化、QA 期間の確保 |
| T-6 | 分析基盤が無い | どこで離脱しているかが分からず、改善の当てが主観になる | 同意取得のうえで最小限の計測を導入(プライバシーポリシーとセット) |
| T-7 | テストマップ削除の後始末 | リリース前に動作確認用マップを一覧から削除する。一覧から外すだけなら影響は小さい(激ムズマップの解放条件は元から集計対象外)。ただし `testMap.ts` はテストの共通フィクスチャとして複数のテストファイルから参照されているため、ファイルごと削除する場合は差し替えが必要 | 一覧からの削除と、既存ユーザーの localStorage に残るテストマップのクリア記録・中断データの扱いを Phase 3〜4 で決める |

### 3.4 事業・運営

| # | 課題 | 内容 | 対応方針 |
|---|---|---|---|
| B-1 | **収益の不確実性** | 2.5 の試算は幅が大きく、標準シナリオでも開発費と同等。単体黒字を約束できない | 段階ゲート方式で投資を分割。Phase 1 の検証結果で判断 |
| B-2 | 販促の担い手が未定 | インディーゲームの売上はウィッシュリスト獲得(発売前の告知活動)でほぼ決まるが、その担当・工数が未定 | 発売の 3〜6 か月前から告知を開始する前提で体制を確保 |
| B-3 | 発売後のサポート | 問い合わせ窓口・返金対応・不具合修正・アップデートの運用が未定 | 窓口と対応時間を決め、運用コストを見込む |
| B-4 | 販売主体と経理 | 法人販売か個人販売かで、収納代行・入金・税務(消費税・源泉)の扱いが変わる | L-1 とセットで確定 |
| B-5 | 競合の多さ | ターン制ストラテジーは類似作が多く、価格競争になりやすい | 「短時間で終わる」「同一画面対人戦」を差別化軸として打ち出す |

### 3.5 体制

| # | 課題 | 内容 | 対応方針 |
|---|---|---|---|
| O-1 | **属人化** | 実質 1 名の開発。仕様は文書化されテストも厚いが、離脱時の継続性は担保されていない | ドキュメント整備は継続。重要判断は文書で残す |
| O-2 | **期間の長期化** | 個人体制を継続する方針のため、全工程で 7〜12 人月相当を暦 9〜15 か月かけて消化することになる。その間に市場の鮮度・本人のモチベーションが落ちるリスクがある | Phase を短く区切り、各 Phase の終わりに「動くもの」をブラウザ版として公開して反応を得ることで、手応えを絶やさない |
| O-3 | **一人で担う職能の幅** | 外注しないため、企画・実装・アート・サウンド・販促・サポートをすべて 1 名で担う。とくに**アートと販促は未経験領域**で、ここがボトルネックになりやすい | アートは Phase 2 の試作で早期に力量を確認する(3.2 P-1)。販促は会社の広報チャネルを使えるかを含めて相談したい |
| O-4 | 客観的な品質判断ができない | 内製かつ 1 名のため、「商品として通用するか」を身内の目でしか測れない | Phase 1・Phase 2 のゲートでは、必ず**社外・関係者以外のテスターの評価**を判定材料にする |

### 3.6 リスク一覧

| リスク | 影響 | 可能性 | 対策 |
|---|---|---|---|
| IP の権利帰属が決まらず着手できない | 大 | 中 | **最優先で決着させる。他の作業に先行して着手** |
| **内製アートが有料商品の水準に届かない** | 大 | 中 | Phase 2 の試作で早期に判定。届かない場合はアセット購入・部分外注・無料公開の継続へ方針転換 |
| 売上が悲観シナリオを下回る | 中 | 中 | 外注しないため金銭的損失は実費のみ。失うのは投じた時間。段階ゲートで早期に撤退できるようにする |
| 開発が長期化しモチベーション・鮮度が落ちる | 中 | **高** | 個人体制のため暦 9〜15 か月かかる。Phase を短く区切り、各 Phase の終わりに動くものを公開する |
| タイトル商標が使えず改題になる | 中 | 中 | Phase 2 の早期に調査。仮題のまま進めない |
| 有料化により無料ユーザーから反発が出る | 小 | 低 | ブラウザ版を体験版として無料で残す方針を明示 |
| 既存作品との類似を指摘される | 中 | 低 | 現行のオリジナル方針を厳守。全素材を内製するため混入リスクは低い |
