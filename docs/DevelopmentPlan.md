# Development Plan

## 開発方針

まずはゲームの核となる「マップ上でユニットを選択し、移動し、攻撃し、ターンを切り替える」部分を完成させます。
その後、占領・収入・生産・AIを段階的に追加します。

## Phase 0: 企画と仕様整理

### 目的

実装前に、最小版のゲーム仕様と作業順を明確にします。

### タスク

- ゲーム概要を整理する
- ユニット仕様を整理する
- 地形仕様を整理する
- MVPの完成条件を定義する
- 今後の拡張候補を分離する

### 成果物

- `docs/GameDesign.md`
- `docs/UnitSpec.md`
- `docs/TerrainSpec.md`
- `docs/DevelopmentPlan.md`

## Phase 1: プロジェクト初期構築

### 目的

TypeScript + Phaser + Vite で開発できる土台を作ります。

### タスク

- Vite + TypeScriptプロジェクトを作成する
- Phaserを導入する
- Git管理対象と除外対象を整理する(`.gitignore` をNode向けに整備)
- Vitestを導入し、テストが実行できることを確認する
- ESLint / Prettierを設定する
- 基本シーン(Phaser Scene)を作成する
- 基本フォルダ構成を作る
- GitHub Pagesへのデプロイ(GitHub Actions)を設定する

### 推奨フォルダ構成

```text
src/
  core/      // ゲームロジック(描画非依存。ユニットテスト対象)
    ai/
    battle/
    economy/
    map/
    progress/
    turn/
    units/
  data/      // ユニット・地形・マップのJSONデータ定義
  scenes/    // PhaserのScene(起動・マップ選択・メイン)
  ui/        // UI表示コンポーネント
  assets/    // スプライト・タイル・効果音
tests/       // Vitestによるロジックのテスト
```

### 設計方針

ゲームロジック(`src/core/`)はPhaserに依存させず、純粋なTypeScriptとして実装します。
これにより移動範囲計算・ダメージ計算・AIをブラウザなしでテストできます。

## Phase 9: 簡易AI

### 目的

敵軍が最低限の行動を取れるようにします。

### タスク

- 敵ユニット一覧を取得する
- 攻撃可能な敵がいる場合は攻撃する
- 攻撃できない場合は最寄りの敵に近づく
- 歩兵が占領可能な場合は占領する
- 資金があれば工場でユニットを生産する

### AI優先順位

1. 攻撃可能なら攻撃
2. 占領可能なら占領
3. 近くの敵へ移動
4. 生産可能なら生産
5. 何もできなければ待機

夜戦では AI も自軍と同じ視界のルールに従う(見えない敵は狙わない・進路上で出くわしたら
強制待機・敵が見えないときは自軍所有でない拠点へ向かって索敵する)。

### 思考パターンと対戦キャラクター

マップ選択画面で対戦相手(敵軍の指揮官)を選べるようにし、指揮官ごとに思考パターンを紐づける。
上記の優先順位は共通で、「どこへ近づくか」と「何を生産するか」だけが思考パターンで変わる
(接近には間合い・隊列の味付けが加わることがある)。

- 思考パターンのパラメータは `src/core/ai/AiBehavior.ts`、指揮官のデータは `src/data/aiCharacters.ts`
- 選択 UI は `src/rendering/AiCharacterWindow.ts`(左に一覧・右に詳細のウィンドウ)。
  指揮官が増えても一覧をスクロールして選べるようにしてある
- 教導官ノーラ(初級〜中級): 当初からの思考パターンをそのまま残したもの
- 突撃長ガルム(中級〜上級): 歩兵をそろえて中立都市を制圧し、資金を貯めて強力なユニットを生産する。
  敵が見えていなくても、通れるマスをたどって(直線ではなく回り込んで)相手の本拠地へ向かう
- 猟兵長ヴェスパ(上級): 編成表(歩兵 4・偵察車 1)を切らさず補充し、そろったあとは
  「すでに持っている種別しか買えないターン」を見送って一段上のユニットのために資金を貯める
  (戦力で負けているあいだは貯めず、買えるものを買って頭数を戻す)。
  間接攻撃ユニットは射程に収まるマスへ構え、前進は味方から 2 マス以内に留める。
  夜戦では視界 2 マス未満の種別(重戦車・自走砲など)を買わない
- 経路の長さは `src/core/movement/PathDistance.ts`(地形だけを見たダイクストラ法)で求める

### 輸送(思考パターンによらず共通)

海で分断されたマップ(分断列島マップなど)で敵AIが攻め込めるよう、輸送の判断は全指揮官に
共通の行動として持たせる。運ぶ相手は占領できるユニット(歩兵)だけ。

- **搭乗**: 歩いて行ける未所有の拠点が占領役の数より少なくなったら、余った歩兵が
  「自分では行けない土地まで運べる」味方の輸送ユニットへ乗り込む
- **輸送**: 積んでいる輸送ユニットは戦わず、乗り込んだ場所から歩いては行けない拠点を目指し、
  降ろした先からその拠点へ歩ける岸へ寄せて降ろす
- **待ち合わせ**: 空の輸送艦は浜辺・自軍の港(港をふさがないよう浜辺を優先)で待ち、
  輸送ヘリ・輸送車は最寄りの味方歩兵のそばへ寄る
- **生産**: 港なら輸送艦・空港なら輸送ヘリを 1 体だけ。代金が貯まるまでは他の拠点の生産を見送る
- あわせて、行き先(経路のつながる相手ユニット・未所有の拠点)が無い種別は生産しない。
  また自軍の生産拠点では足を止めない(居座ると生産が止まるため)

詳細は docs/GameDesign.md「敵AI」を参照。

### サウンドの実装方針

音源はすべてオリジナルとするため、外部の音声ファイルを持たず **Web Audio API でファミコン風のチップチューンをコード生成** する。

- `src/audio/notes.ts`: 音名→周波数の変換(純粋ロジック。Vitestでテスト)
- `src/audio/soundDefinitions.ts`: 効果音・BGMの「楽譜データ」(純粋データ。コードから分離)
- `src/audio/SoundEngine.ts`: Web Audio を薄くラップした発音エンジン(トーン・ノイズ)
- `src/audio/SoundManager.ts`: 効果音再生・BGMループ・ミュート・音量調整を統括する高レベルAPI

BGMは自軍テーマ(長調・行進曲風)と敵軍テーマ(短調・緊張感)を用意し、手番で切り替える。
ブラウザの自動再生制限に対応するため、AudioContextは初回のユーザー操作で起動する。
非対応環境(SSR・テスト等)では静かに無効化し、ゲーム進行に影響しない。

ブラウザ(タブ・ウィンドウ)が非アクティブな間は音を鳴らさない。
`SoundManager.bindPageVisibility()` で `visibilitychange`(タブ切替・アプリ切替)と
`blur` / `focus`(別ウィンドウへの切替)を監視し、非アクティブになったらマスター音量を0にしたうえで
AudioContextを一時停止する。復帰時は止めた地点から再開する(ミュート中はミュートのまま)。
シーンを抜けるときは `SoundManager.dispose()` でBGM停止・監視解除・AudioContextの破棄まで行い、
再入場のたびにAudioContextやリスナが残り続けないようにする。
