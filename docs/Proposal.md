# 企画書: グリッドウォーズ(仮題)

| 項目 | 内容 |
|---|---|
| タイトル案 | グリッドウォーズ(仮題) |
| ジャンル | ターン制ウォーシミュレーション |
| プラットフォーム | Webブラウザ(PC推奨)。GitHub Pagesで公開し、URLを開くだけで遊べる形にする |
| 開発環境 | TypeScript + Phaser(2Dゲームエンジン) + Vite |
| プレイ人数 | 1人(vs CPU)。将来的に同一画面での2人対戦を検討 |
| 想定プレイ時間 | 1ステージ 15〜30分 |
| 開発体制 | 個人開発 |
| 本企画書の位置づけ | プロジェクト全体の方向性を定める最上位ドキュメント |

> 注記: 本作は「ファミコンウォーズ」に代表される往年のターン制ウォーシミュレーションのゲーム性から着想を得たオリジナル作品です。名称・グラフィック・音楽・マップ・シナリオ・固有データはすべてオリジナルとして制作し、既存作品の素材・固有表現は使用しません。

## 1. どんなゲームか(ひとことで)

**マス目のマップの上で、部隊を動かし、拠点を奪い、お金を稼ぎ、部隊を生産して、敵の本拠地を落とすターン制の戦争ゲーム。**

プレイヤーと敵軍が交互にターンを進め、以下のループを繰り返します。

```
  ┌─────────────────────────────────────┐
  │  収入を得る → 部隊を生産する → 部隊を動かす   │
  │  → 敵と戦う / 拠点を占領する → ターン終了     │
  └──────────────────┬──────────────────┘
                     └──── 敵ターンへ(同じ流れ)
```

最終的に「敵本拠地の占領」または「敵部隊の全滅」で勝利します。

## 2. コンセプト

### 「considering(考える楽しさ)」を最優先にする

- 反射神経ではなく、**盤面を眺めて次の一手を考える楽しさ**を核にする
- 1ターンごとに区切りがあるため、じっくり考えられて中断もしやすい
- ルールは足し算で覚えられるシンプルさ(移動・攻撃・占領・生産の4動作)

### レトロで見やすいドット絵調

- 低解像度・ドット絵調のグラフィックで、マップとユニットの視認性を最優先
- 1マス=1情報。地形とユニットが一目でわかる記号的なデザイン

### 「地形」と「相性」で戦略が生まれる

- 森や山は守りに強いが移動しにくい。道路は速いが無防備
- 歩兵は安いが弱い。しかし**拠点を占領できるのは歩兵だけ**
- 戦車は強いが高い。自走砲は遠くから撃てるが接近されると脆い
- 「どこで戦うか」「何を作るか」「どの拠点を取るか」の3つの判断が常に発生する

## 3. ターゲット

| 層 | 想定 |
|---|---|
| メイン | ターン制ストラテジー(ウォーズ系・SRPG)経験者。懐かしさと手軽さを求める層 |
| サブ | ストラテジー初心者。ルールが少なく1ステージが短いため入門に向く |

## 4. セールスポイント

1. **インストール不要・URLを開くだけで遊べる**: ブラウザゲームとして公開し、リンク共有だけで誰でもすぐプレイできる
2. **1ステージ完結・短時間で遊べる**: 15〜30分で決着。腰を据えた長編ではなく「もう1回」を誘う設計
3. **覚えることが少ない**: ユニット3種・地形7種から開始。チュートリアルなしでも遊び方がわかる
4. **経済と戦闘の2層構造**: 前線の戦術(どう戦うか)と後方の経営(何を作るか)が噛み合う奥深さ
5. **データ駆動の拡張性**: ユニット・地形・マップはデータ定義で追加でき、継続的なアップデートが容易

## 5. ゲームルール概要

詳細は `docs/GameDesign.md` に定義済み。ここでは骨子のみ示します。

### 基本サイクル

- 自軍ターンと敵軍ターンを交互に繰り返すターン制
- ターン開始時に所有拠点数に応じた収入を獲得
- 各ユニットは1ターンに1回行動(移動+攻撃/占領/待機)
- 工場で資金を消費してユニットを生産

### 勝敗条件

| 勝利 | 敗北 |
|---|---|
| 敵本拠地を占領する | 自軍本拠地を占領される |
| 敵ユニットを全滅させる | 自軍ユニットが全滅する |

### 登場ユニット(MVP時点・詳細は `docs/UnitSpec.md`)

| ユニット | 特徴 | 役割 |
|---|---|---|
| 歩兵 | 安い・弱い・占領可能 | 拠点確保の要。数で運用する |
| 戦車(軽・中・重) | 高コスト・高火力・直接攻撃 | 前線を押し上げる主力。重いほど強く鈍い |
| 自走砲 | 射程2-3の間接攻撃・接近戦不可 | 後方支援。守られてこそ活きる |
| ロケット砲 | 射程3-5の間接攻撃・飛行ユニットは撃てない | 長射程の後方支援。もっとも打たれ弱い |

### 地形(MVP時点・詳細は `docs/TerrainSpec.md`)

平地・森・山・道路の戦闘地形と、都市・工場・本拠地の拠点地形の計7種。
地形は「移動コスト」「防御補正」「占領可否」を持ち、位置取りの判断材料になります。

## 6. 画面イメージ

インゲームの前段にマップ選択画面を挟み、遊ぶマップを選んでからゲーム本編に入る。
マップは今後も増やしていくため、カード一覧は画面に収まらなくなったらスクロールして選べるようにする
(ドラッグ/スワイプ・マウスホイール。スクロールが必要なときだけ右端にスクロールバーを表示する)。

```
【マップ選択画面】
┌──────────────────────────────┐
│           マップを選択           │
│ ┌──────────────────────────┐ │
│ │ 拠点争奪マップ 01              │ │
│ │ サイズ: 横15 × 縦10           │ │
│ │ 中央の拠点を奪い合う横長マップ    │ │
│ └──────────────────────────┘ │
│ ┌──────────────────────────┐ │
│ │ テストマップ 01               │ │
│ │ サイズ: 横10 × 縦10           │ │
│ └──────────────────────────┘ │
└──────────────────────────────┘
```

```
【ゲーム本編】
┌────────────────────────────────────────────────┐
│ ターン 3 / 自軍         資金: 12000 G   [ターン終了] │
├──────────────────────────────┬─────────────────┤
│                              │  選択中ユニット      │
│   マップ (マス数はマップごとに可変)  │  ─────────────    │
│                              │  中戦車            │
│   ・地形タイル                  │  HP  8/10        │
│   ・ユニット                   │  移動 5  射程 1    │
│   ・移動可能範囲 (青ハイライト)    │                 │
│   ・攻撃可能範囲 (赤ハイライト)    │  地形: 森         │
│                              │  防御 ★★         │
└──────────────────────────────┴─────────────────┘
```

- 操作はマウスのみで完結(マップ選択 → クリックで選択 → 移動先クリック → 対象クリック)
- マップの表示領域(ビューポート)には上限を設け、これを超える大きなマップは縮小せず、ドラッグ(スマホのスワイプ)でスクロールして全体を見られるようにする。小さいマップは従来どおり全マスを一度に表示する
- 選択中ユニットのステータス・地形効果・ダメージ予測を常時サイドに表示
- 画面はキャンバスを画面幅いっぱいに拡大して**上寄せ**で表示する(縦持ちのスマホでは下側に余白が寄り、指で操作しやすくなる)。現在のレイアウトは横長(マップ + 右サイドの情報パネル)のため、縦持ち時の表示サイズはこの縦横比で頭打ちになる。縦持ち専用レイアウト(情報パネルをマップの下へ配置)は今後の検討課題とする
- 決着後のリザルト画面から「マップ選択へ戻る」で別マップを続けて遊べる

## 7. 開発スコープ

### MVP(最初のゴール)

「10x10のマップ1枚を、CPU相手に最後まで遊んで勝敗がつく」状態。
完成条件の詳細は `docs/GameDesign.md` の「MVPの完成条件」に定義済み。

- マップ表示・ユニット選択・移動・攻撃・撃破
- 占領・収入・生産の経済ループ
- 簡易AI(攻撃 > 占領 > 前進 > 生産の優先順位)
- 勝敗判定とリザルト表示

### MVP後の拡張候補(優先順)

1. マップ追加(3〜5ステージ) ※ステージ選択画面は実装済み
2. ユニット追加(偵察車・対空戦車・航空ユニットなど)
3. 索敵(霧)・弾薬・燃料などの上級ルール
4. 同一画面2人対戦
5. マップエディタ

### やらないこと(スコープ外)

- オンライン対戦
- キャンペーンシナリオ・ストーリー演出
- 3Dグラフィック

## 8. 開発計画

実装は `docs/DevelopmentPlan.md` のPhase 0〜10に従って段階的に進めます。

| 段階 | 内容 | 対応Phase |
|---|---|---|
| 企画 | 企画書・仕様書の整備(本書) | Phase 0 |
| 基盤 | Vite + Phaserプロジェクト構築・マップ表示 | Phase 1〜2 |
| コア | ユニット・移動・攻撃・ターン管理 | Phase 3〜6 |
| 経済 | 占領・収入・生産・勝敗判定 | Phase 7〜8 |
| 対戦 | 簡易AI | Phase 9 |
| 仕上げ | UI・演出・効果音 | Phase 10 |

各Phaseの完了ごとに「動くもの」を確認しながら進め、コアループ(Phase 6まで)を最優先で完成させます。

## 9. リスクと対策

| リスク | 対策 |
|---|---|
| 仕様の肥大化で完成しない | MVPの完成条件を固定し、拡張はMVP後に回す |
| AIの実装難航 | まずプレイヤー操作のみで両軍を動かせる状態を作り、AIは後付けする |
| バランス調整の泥沼化 | パラメータをJSONデータとして外部化し、ロジックを触らず調整できるようにする |
| 既存作品との類似 | 名称・ビジュアル・データはすべてオリジナル。ゲームシステムのみ参考にする |
